Module 1: Program Storage & Stack

Program Memory, Program Counter & Stack

Program Memory contains sequential cells storing machine instructions. The Program Counter (PC) tracks the current instruction address, while the hardware Stack stores return addresses during subroutine calls and interrupts.

Program Counter

Generates instruction addresses continuously to advance execution through Program Memory.

Call/Return Stack

Dedicated hardware stack automatically pushes PC address during CALLs and restores it on RETURNs.

Capacity Limit

Program memory cell capacity determines maximum application program size and instruction depth.

Module 2: Data Memory Architecture

Data RAM: GPR, SFR & Banked Addressing

Data RAM stores volatile operational state. Registers are split into user variables (GPR) and hardware controls (SFR), grouped into memory banks.

GPR

General Purpose Registers

Serves as RAM workspace for storing application proccessing data and program logic state variables.

SFR

Special Function Registers

Specialized registers hardwired to hardware peripherals (I/O ports, timers, status flags) to monitor and control microcontroller operations.

Module 4: ALU Execution & Routing

ALU Pathways, MUX & Result Destinations

The ALU executes single-operand or dual-operand functions. Operands pass through a Multiplexer (MUX), with computation outcomes directed back to the Working Register ($W$) or RAM memory.

Single vs. Dual Operand Execution

  • Single Operand: Operation targets either Working Register $W$ or a designated RAM cell directly.
  • Dual Operand: Operand 1 comes from Working Register $W$, while Operand 2 is routed via the Multiplexer (MUX) from RAM or instruction literal constants.

Result Destination Logic

Every instruction opcode contains a destination flag bit specifying where the result of the ALU operation is written back upon completion:

Destination -> W Register
Destination -> RAM Cell

STATUS Register Integration

ALU computations update arithmetic flag bits in the STATUS register (e.g. Zero flag, Carry flag, Digit Carry flag), which conditional branch instructions evaluate for program flow control.

Module 5: Hardware Protection Timers

Watchdog Timer (WDT), PWRT & OST

Hardware protective timers guarantee software stability, ensure supply rail stabilization, and confirm oscillator signal integrity prior to CPU code execution.

Watchdog Timer (WDT)

Runs independently via dedicated internal RC oscillator. Triggers system reset if software loops freeze and fail to issue periodic clear instructions.

Power-Up Timer (PWRT)

Holds CPU in reset state for a fixed duration after power connection to allow supply voltage ($V_{DD}$) to reach operational levels.

Oscillator Start-up Timer (OST)

Delays execution for a set count of clock cycles following PWRT expiration, ensuring crystal clock amplitude and frequency lock in.

Module 6: Clocking & Low-Power Operation

Clock Generator & Power Management (SLEEP)

The clock generator supplies periodic timing pulses that dictate CPU instruction speed. Low-power execution modes (SLEEP/STOP) halt clocks to conserve energy.

Clock Speed & Throughput

Higher oscillator clock frequencies yield proportionally higher CPU instruction throughput (MIPS). Oscillators can be internal or driven by external quartz crystals.

Power Saving (SLEEP Mode)

Halts internal core clocks, reducing power consumption to microamps. System exits SLEEP upon receiving peripheral interrupts, WDT timeout, or external resets.
